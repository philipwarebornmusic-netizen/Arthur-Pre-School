ärtan – Supabase setup

Configuration
- Project URL and publishable key live in ../supabase-config.js.
- The publishable key is safe for the browser. Never commit a secret/service-role key.
- Authentication uses Supabase email/password accounts.

Database installation or upgrade
1. Open Supabase Dashboard -> SQL Editor -> New query.
2. When upgrading the previous Arthur pilot database, paste and run all of 000_upgrade_from_arthur.sql as a separate query.
3. Open another new query, then paste and run all of schema.sql.
4. No seed file is used. The application starts empty and creates real data through onboarding.

Together, the upgrade preflight and schema handle both a new database and the previous Arthur pilot schema. They:
- creates the production tables, indexes and RPC functions;
- installs organization-scoped row-level security;
- supports organization and school creation;
- supports email-bound invitations for staff and guardians;
- lets guardians maintain child, health, contact and consent information;
- removes the known Solgläntan demo organization and exact @arthur.test accounts.

Required Supabase Auth setting
- Set the Site URL to the deployed app origin.
- Add local/deployment redirect URLs if email confirmation is enabled.
- Keep leaked-password protection and email confirmation enabled for production.

First real account
1. Open the app and create an account.
2. Confirm the email if required, then log in.
3. Choose "Starta en organisation" and provide organization, first school and first department.
4. Add children under Personer.
5. Invite staff by department and guardians by child. Invitations are restricted to the exact email address entered.

Deployment
Serve the repository root as a static site. index.html loads supabase-config.js before app.js. Apply schema.sql before accepting users; otherwise the production RPC functions are unavailable.
Production URL: https://artanperschool.netlify.app/
Use this exact origin as the Supabase Auth Site URL and allowed redirect URL.
